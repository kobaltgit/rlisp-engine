# Аппаратный 3D-конвейер на WebGPU (WGPU 3D Pipeline)

Руководство для мейнтейнера и разработчиков движка `rlisp-engine`.

Документ описывает перенос 3D-конвейера с программной растеризации на CPU на аппаратный GPU через WebGPU/WGSL (фича `--features wgpu`), внутреннюю архитектуру конвейера, решённые краевые случаи и правила дальнейшей поддержки.

---

## 1. Концепция и архитектурные инварианты

В версиях до v0.3 бэкенд `wgpu` ускорял исключительно 2D-растр (`clear`, `fill-rect`, `blit`, `blit-tex`), а весь 3D-конвейер (`render3d.rs`) выполнялся программно на одном ядре CPU: преобразование вершин T&L, проверка Z-буфера, перспективная интерполяция атрибутов и затенение треугольников. На сложных сценах (10–13 тыс. полигонов в `island.lisp`) это упиралось в 20–30 FPS на процессоре.

Нововведение реализует **полный аппаратный 3D Render Pipeline на WebGPU/WGSL**:
1. **Zero-Core Hardcoding**: ни одной строчки Lisp-кода в `assets/lisp/` не изменено. Скрипты сцен (`island.lisp`, `render3d.lisp`, `materials.lisp`, `main_island.lisp`) вызывают те же высокоуровневые DSL-примитивы (`gpu3d-mesh`, `gpu3d-mesh-vc`, `draw-batch-tex`, `gpu3d-clear`).
2. **Zero-Dependency**: сборка по умолчанию компилируется без `wgpu` и внешних зависимостей (`cargo test --workspace -j 1`).
3. **Прозрачный откат (Fallback)**: на машинах без поддерживаемого GPU-адаптера или в headless CI движок автоматически откатывается на программный растр `Backend::Software`.
4. **Единый композитный фреймбуфер (`fb`)**: аппаратный GPU-слой рендерится в offscreen-текстуру и при вызове `flush` переносится в `Hal::fb` через альфа-композит, поэтому веб-редактор (`--serve`), PNG-захват (`--capture`) и MCP-инструменты работают идентично на обоих бэкендах.

## 2. Архитектура и компоненты

### 2.1. Стек модулей

```
┌─────────────────────────────────────────────────────────────┐
│ assets/lisp/ (render3d.lisp, island.lisp, materials.lisp)   │
│ Матрицы 4x4, камера, материалы, меши, батчи инстансов       │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ src/render3d.rs (HAL DSL-биндинги)                          │
│ Маршрутизация: Software (CPU-растр) vs Wgpu (GPU-конвейер)  │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ src/gpu.rs (WgpuRenderer: trait GpuBackend)                 │
│ Буферы вершин/индексов/инстансов, offscreen-таргет, Z-буфер │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ src/gpu_3d.rs (Pipeline3D + SHADER_3D WGSL)                 │
│ T&L, Blinn-Phong, туман, альфа-тест, 8 вариантов пайплайнов │
└─────────────────────────────────────────────────────────────┘
```

### 2.2. Модуль `src/gpu_3d.rs`

Содержит шейдер WGSL `SHADER_3D` и менеджер пайплайнов `Pipeline3D`:

- **Вершинные точки входа**:
  - `vs_3d`: рендеринг одиночных мешей. Принимает `pos (xyz)`, `uv`, `rgba (per-vertex color)`. Вычисляет позицию в мировом пространстве через `u.model` и переводит в NDC через `u.mvp`.
  - `vs_3d_instanced`: аппаратный instancing для сотен объектов в одном draw call. Принимает атрибуты инстанса: трансляцию `inst_trans`, масштаб `inst_scale`, углы Эйлера `inst_rot (yaw, pitch, roll)` и тинт `inst_tint`. Поворот вычисляется матрицей `Ry * Rx * Rz` прямо в вершинном шейдере.
- **Коррекция диапазона глубины NDC**:
  Матрицы Lisp-пайплайна (`mat-perspective` в `render3d.lisp`) используют конвенцию OpenGL ($Z_{clip} \in [-W, +W]$). Для WebGPU ($Z_{ndc} \in [0, 1]$) в вершинном шейдере выполняется перевод:
  $$\text{clip.z} = (\text{clip.z} + \text{clip.w}) \times 0.5$$
- **Фрагментные точки входа**:
  - `fs_3d`: затенение монолитных и per-vertex мешей;
  - `fs_3d_tex`: текстурированные меши с поддержкой repeat-тайлинга (`u.tiling`), альфа-теста (`u.alpha_test`), Blinn-Phong и тумана;
  - `fs_3d_wire`: каркасный рендеринг (линии).
- **Освещение и туман**:
  - Направленный диффузный свет: $\text{shade} = \text{clamp}(\text{ambient} + \text{diffuse} \times \max(\mathbf{N} \cdot \mathbf{L}, 0.0), 0.0, 1.0)$ для непрозрачных объектов; для двусторонних прозрачных — с $\text{abs}(\mathbf{N} \cdot \mathbf{L})$;
  - Блик Blinn-Phong: полувектор $\mathbf{H} = \text{normalize}(\mathbf{L} + \mathbf{V})$ по мировой позиции камеры $\mathbf{V} = \text{normalize}(\text{camera\_pos} - \text{world\_pos})$, затухание $\text{pow}(\max(\mathbf{N} \cdot \mathbf{H}, 0.0), \text{shininess})$;
  - Экспоненциальный туман: $f = 1.0 - \exp(-\text{fog\_density} \times \text{depth})$.

### 2.3. Семейство пайплайнов (Render Pipelines)

Для корректной отрисовки смешанной сцены сконфигурированы 8 комбинаций конвейеров:

| Пайплайн | Вход | Текстура | Depth Write | Режим блендинга | Применение |
|---|---|---|---|---|---|
| `pipeline_solid` | Vertex | Нет | **Да** | None | Геометрия без текстур |
| `pipeline_tex` | Vertex | Да | **Да** | None | Ландшафт, скалы, стволы |
| `pipeline_blend_solid` | Vertex | Нет | **Нет** | `ALPHA_BLENDING` | Вода, тени с per-vertex alpha |
| `pipeline_blend_tex` | Vertex | Да | **Нет** | `ALPHA_BLENDING` | Полупрозрачные меши |
| `pipeline_blend_tex_depth` | Vertex | Да | **Да** | `ALPHA_BLENDING` | Текстурированные объекты с мягким краем |
| `pipeline_inst_solid` | Instanced | Нет | **Да** | None | Батчи монолитных тел |
| `pipeline_inst_tex` | Instanced | Да | **Да** | None | Батчи камней, стволов |
| `pipeline_inst_blend_solid`| Instanced | Нет | **Нет** | `ALPHA_BLENDING` | Батчи спецэффектов |
| `pipeline_inst_blend_tex` | Instanced | Да | **Нет** | `ALPHA_BLENDING` | Облака, дым (`blend < 0.90`) |
| `pipeline_inst_blend_tex_depth`| Instanced | Да | **Да** | `ALPHA_BLENDING` | Кроны деревьев, пальмы, трава (`blend >= 0.90`) |
| `pipeline_wire` | Vertex | Нет | **Нет** | None | Режим каркаса |

## 3. Решённые технические вызовы (Post-Mortem & Gotchas)

### 3.1. Устранение просадки FPS и множественных синхронизаций
- **Проблема**: В `render3d.rs` в начале `mesh_draw` и `batch_draw` стоял вызов `hal.flush_gpu()`. В программном режиме это было безвредно, но в `wgpu` вызывало `device.poll(Maintain::Wait)` и `map_async` синхронное чтение в память CPU до 20 раз за один кадр, просаживая FPS до 12–17.
- **Решение**: Вызовы `flush_gpu()` отключены для `Backend::Wgpu`. Команды кадра аккумулируются на GPU и сабмитятся вместе с композитом один раз в конце кадра.

### 3.2. Композит полупрозрачных пикселей (`composite_readback`)
- **Проблема**: Функция `composite_readback` проверяла `if src[s + 3] == 255`. Все пиксели с альфой менее 255 (кроны деревьев `blend = 0.96`, пальмы `0.98`, трава `0.95`, облака `0.88`, тени и вода) отбрасывались и замещались фоновым небом.
- **Решение**: Реализован честный $src\_over$ альфа-блендинг для $a > 0$:
  ```rust
  let inv_a = 255 - a;
  fb[d] = ((src[s] as u32 * a + fb[d] as u32 * inv_a) / 255) as u8;
  ```

### 3.3. Перекрытие холма водой (изоляция состояния `r3.blend`)
- **Проблема**: В `island.lisp` облака в конце кадра выставляли `(gpu3d-alpha-blend 0.88)`. В следующем кадре функция `gpu3d-clear` очищала цвет и Z-буфер, но не сбрасывала `r3.blend`. Из-за этого ландшафт острова рендерился с `depth_write: false` (как полупрозрачный) и не оставлял следа в Z-буфере. Вода, рисуясь позже, перекрывала холм.
- **Решение**: В `hal.clear_3d()` добавлен обязательный сброс `self.r3.blend = 1.0`, гарантирующий, что начало каждого 3D-кадра всегда непрозрачно и заполняет буфер глубины.

### 3.4. Отсечение воды за кронами деревьев
- **Проблема**: Кроны деревьев и листья пальм рисовались с `blend: 0.96..0.98` и `depth_write: false`. Вода, занимающая бесконечную плоскость горизонта, не видела глубины крон и разрезала деревья горизонтальной полосой.
- **Решение**: Для плотной листвы (`blend >= 0.90`) задействован пайплайн с `depth_write: true` в сочетании с отсечением прозрачных пикселей в фрагментном шейдере (`if texel.a <= thr { discard; }`). Прозрачные поля текстуры не засоряют Z-буфер, а видимая хвоя/листва получает глубину и корректно отсекает воду позади себя.

### 3.5. Защита от паники на пустых срезах (`Buffer slices can not be empty`)
- **Проблема**: Метод `wgpu::Buffer::slice(start..end)` в спецификации WebGPU выбрасывает панику, если `start == end`.
- **Решение**: В `draw_mesh_3d` и `draw_batch_3d` добавлены защитные проверки на нулевую длину: `if pos.is_empty() || idx.is_empty() || insts.len() < 12 { return Ok(0); }`.

## 4. Инструкция для мейнтейнера

### 4.1. Сборка и прогон тестов

> [!IMPORTANT]
> При компиляции и тестах **строго соблюдать флаг ограничения потоков `-j 1`** во избежание перегрузки CPU машины разработчика!

```powershell
# 1. Проверка базовой сборки (zero-dependency, программный растр)
cargo test --workspace -j 1

# 2. Проверка аппаратного конвейера wgpu
cargo test --workspace --features wgpu -j 1
```

### 4.2. Проверка визуального вывода сцены «Остров»

```powershell
# Запуск захвата 30 кадров с аппаратным WGPU
cargo run --release --features wgpu -j 1 -- --script assets/lisp/main_island.lisp --wgpu --capture wgpu_test --every 10 --frames 30 --fast
```

Критерии правильного вывода:
1. Ландшафт острова четко возвышается над водой, песчаный берег переходит в морское дно;
2. Вода прозрачна, имеет градиент глубины, пену у берега и блик на волнах;
3. Кроны сосен и пальмовые листья имеют пышный силуэт, не перекрываются водой на горизонте;
4. Под деревьями, камнями и фонарём видны мягкие полупрозрачные тени;
5. Небо плавно уходит в туман; в левом верхнем углу отображается счетчик полигонов и FPS.

### 4.3. Запуск веб-редактора с аппаратным 3D

```powershell
cargo run --release --features wgpu -j 1 -- --serve --wgpu --script assets/lisp/main_island.lisp
```
Открыть в браузере `http://127.0.0.1:7300`. Управление камерой 3D доступно по зажатию правой кнопки мыши и клавишам WASD.
