# 3D-конвейер нового поколения: от программного Flat Shading до аппаратного WebGPU 3D

Руководство для мейнтейнера и архитектурный обзор этапа разработки `rlisp-engine`.

---

## 1. Обзор нововведения и исторический контекст

До текущего этапа 3D-подсистема движка представляла собой фиксированный программный растеризатор на одном ядре CPU:
* **Только Flat shading (плоские грани):** нормаль вычислялась одна на весь полигон через векторное произведение вершин треугольника `(v1 - v0) × (v2 - v0)`. Любые круглые объекты (стволы пальм, бутылки, фонари, холмы острова) выглядели угловатыми («лоу-поли»), а блик от солнца ломался на стыках треугольников.
* **WGPU ускорял только 2D-слой:** при флаге `--wgpu` аппаратно рисовались только `clear`, `fill-rect` и `blit`. Все 13 000 полигонов острова (`island.lisp`) обсчитывались программно на CPU.
* **Падение FPS:** программный растр с мягкими тенями, полупрозрачной водой и тысячами инстансов упирался в 17–28 FPS.

В рамках данной разработки совершён **полный технологический скачок 3D-архитектуры**:
1. **Программный растеризатор на CPU** получил интерполяцию сглаженных нормалей и попиксельный шейдинг Blinn-Phong;
2. **Создан аппаратный 3D-конвейер WebGPU** (`src/gpu_3d.rs`) с 8 пайплайнами, аппаратным Z-буфером, текстурированием, Blinn-Phong, туманом и аппаратным instancing'ом сотен объектов за один draw call;
3. **Внедрена подсистема кэширования геометрии в VRAM (VBO/IBO Mesh Caching)**, устранившая постоянную пересылку мешей по шине PCIe;
4. **Реализован On-Demand GPU Readback**, избавивший игровой цикл от синхронных блокировок CPU (`poll(Maintain::Wait)`);
5. **Обеспечена бесшовная интеграция с веб-редактором** (`--serve` на порту 7300) без изменения кода скриптов (Zero-Core Hardcoding).

## 2. Архитектура: два равноправных бэкенда рендера

Движок сохраняет принцип **честного паритета**: один и тот же Lisp-код (`render3d.lisp`, `island.lisp`) исполняется без единого изменения на обоих бэкендах:

```
                      ┌──────────────────────────────────────┐
                      │    Lisp DSL (assets/lisp/*.lisp)     │
                      │  draw-mesh, draw-batch, gpu3d-*      │
                      └──────────────────┬───────────────────┘
                                         │
                                         ▼
                      ┌──────────────────────────────────────┐
                      │       HAL Фасад (src/hal.rs)         │
                      │   Диспетчеризация по бэкенду        │
                      └──────────┬────────────────┬──────────┘
                                 │                │
            ┌────────────────────┘                └────────────────────┐
            ▼                                                          ▼
┌───────────────────────────────┐              ┌──────────────────────────────────────┐
│  Бэкенд 1: Software CPU       │              │  Бэкенд 2: Hardware WebGPU           │
│  (src/render3d.rs)            │              │  (src/gpu.rs + src/gpu_3d.rs)        │
├───────────────────────────────┤              ├──────────────────────────────────────┤
│ • Сканлайн-растеризатор       │              │ • WGSL шейдер (SHADER_3D)            │
│ • Перспективная интерполяция  │              │ • 8 вариантов RenderPipeline         │
│ • Сглаженные нормали (Phong)  │              │ • Аппаратный Z-буфер (Depth32Float)  │
│ • Программный Z-буфер         │              │ • VBO/IBO кэш в VRAM (MeshKey)       │
│ • Zero-Dependency по умолч.   │              │ • Аппаратный Instancing (vs_3d_inst) │
│ • Вывод: прямая запись в fb   │              │ • Вывод: Offscreen target + Readback │
└───────────────────────────────┘              └──────────────────────────────────────┘
```

## 3. Компонент 1: Сглаженные нормали и шейдинг Фонга (CPU & GPU)

### 3.1. Математика интерполяции в программном растре (`src/render3d.rs`)
В структуру вершины `Vtx` добавлены перспективно-взвешенные компоненты нормалей:
$$nx\_w = \frac{N_x}{W}, \quad ny\_w = \frac{N_y}{W}, \quad nz\_w = \frac{N_z}{W}$$

В цикле инкрементального сканлайна строки треугольника:
1. Вычисляются пошаговые дельты атрибутов вдоль оси X: $\frac{dnx}{dx}, \frac{dny}{dx}, \frac{dnz}{dx}$;
2. Для каждого пикселя нормаль восстанавливается умножением на текущий $W = \frac{1}{inv\_w}$;
3. Вектор нормализуется: $\mathbf{N} = \text{normalize}(nx, ny, nz)$;
4. Вычисляется диффузный свет Ламберта: $\text{diffuse} = \max(\mathbf{N} \cdot \mathbf{L}, 0.0)$;
5. Вычисляется блик Блинна-Фонга через полувектор:
   $$\mathbf{H} = \text{normalize}(\mathbf{L} + \mathbf{V}), \quad \text{spec} = (\max(\mathbf{N} \cdot \mathbf{H}, 0.0))^{\text{shininess}}$$

### 3.2. Поддержка в Lisp DSL
- Примитив `(gpu3d-shading 'flat | 'smooth)` задаёт глобальный режим затенения.
- В структуре материалов `materials.lisp` добавлен атрибут `:shading`:
  ```lisp
  (defmaterial 'пальма-ствол
    :color '(0.58 0.44 0.32)
    :diffuse 0.90
    :specular 0.20
    :shininess 16
    :shading 'smooth)
  ```
- Процедурные генераторы `mesh-cylinder` и `mesh-sphere` в `render3d.lisp` генерируют аналитические единичные нормали вершин.
- Функция `mesh-compute-smooth-normals` усредняет нормали разделяемых вершин произвольных полигональных сеток.
- Загрузчик `load-gltf.lisp` читает стандартный буфер атрибутов `NORMAL` из glTF-файлов.

## 4. Компонент 2: Аппаратный 3D-конвейер WebGPU (`src/gpu_3d.rs`)

### 4.1. Шейдер WGSL (`SHADER_3D`)
- **Единый буфер Uniforms (`Uniforms3DRaw`, выравнивание 16 байт):** матрицы `model` и `mvp`, вектор света, параметры Blinn-Phong (`ambient, diffuse, spec, shininess`), позиция камеры, прозрачность `blend`, repeat-тайлинг `tiling`, плотность и цвет тумана.
- **Коррекция глубины NDC:** перевод диапазона $Z_{clip} \in [-W, +W]$ (конвенция OpenGL в `mat-perspective`) в диапазон $Z_{ndc} \in [0, 1]$ WebGPU прямо в вершинном шейдере:
  $$\text{clip.z} = (\text{clip.z} + \text{clip.w}) \times 0.5$$
- **Аппаратный Instancing (`vs_3d_instanced`):**
  Каждый инстанс передаётся компактной структурой из 12 `f32`:
  - `inst_trans (xyz)` — мировые координаты;
  - `inst_scale (xyz)` — масштаб по осям;
  - `inst_rot (yaw, pitch, roll)` — углы Эйлера (матрица вращения $R_y \times R_x \times R_z$ формируется на GPU);
  - `inst_tint (rgb)` — индивидуальный цветовой оттенок.

### 4.2. Семейство из 8 пайплайнов (Pipeline State Matrix)

| Пайплайн | Вход | Текстура | Depth Write | Режим блендинга | Назначение |
|---|---|---|---|---|---|
| `pipeline_solid` | Одиночный | Нет | **Да** | None | Базовая непрозрачная геометрия |
| `pipeline_tex` | Одиночный | Да | **Да** | None | Ландшафт, скалы, песчаный берег |
| `pipeline_blend_solid` | Одиночный | Нет | **Нет** | `ALPHA_BLENDING` | Прозрачные меши (вода, тени) |
| `pipeline_blend_tex` | Одиночный | Да | **Нет** | `ALPHA_BLENDING` | Мягкие полупрозрачные объекты |
| `pipeline_blend_tex_depth` | Одиночный | Да | **Да** | `ALPHA_BLENDING` | Текстуры с альфа-тестом и глубиной |
| `pipeline_inst_solid` | Инстансы | Нет | **Да** | None | Батчи камней и монолитных тел |
| `pipeline_inst_tex` | Инстансы | Да | **Да** | None | Батчи текстурированных стволов |
| `pipeline_inst_blend_tex` | Инстансы | Да | **Нет** | `ALPHA_BLENDING` | Облака, дым (`blend < 0.90`) |
| `pipeline_inst_blend_tex_depth` | Инстансы | Да | **Да** | `ALPHA_BLENDING` | Листва пальм, кроны сосен (`blend >= 0.90`) |

## 5. Компонент 3: Оптимизация шины и памяти (VBO Caching & On-Demand Readback)

### 5.1. VBO/IBO Mesh Caching
* **Проблема:** Каждый кадр геометрия острова и объектов сериализовалась в ОЗУ и заново заливалась в буферы GPU через PCIe, вызывая memory churn.
* **Решение:**
  * Введён хэш-ключ `MeshKey` на базе быстрого семплирования `calc_mesh_fingerprint` (FNV-1a хэш по выборке из 16 равноотстоящих вершин/индексов). Проверка занимает доли микросекунды ($O(1)$);
  * Геометрия кэшируется в `HashMap<MeshKey, CachedGpuMesh>` с буферами `Arc<wgpu::Buffer>`;
  * Статический ландшафт заливается в VRAM **один раз** при старте. Аллокации памяти за кадр снижены до **0 байт**;
  * При перезагрузке текстур/скриптов кэш автоматически сбрасывается (`clear_mesh_cache()`).

### 5.2. On-Demand GPU Readback
* **Проблема:** Вызов `self.device.poll(Maintain::Wait)` на каждом кадре блокировал поток CPU, снижая FPS видеокарты уровня RTX 4060 до 14–16.
* **Решение:**
  * Фреймбуфер читается из GPU в RAM **только тогда, когда он запрошен внешним клиентом** (веб-редактором через HTTP `/frame.png` или флагом `--capture`);
  * Если запроса нет, GPU исполняет команды асинхронно на максимальной частоте;
  * Время рендера чистых кадров снизилось до **13.8–16.1 мс (62–72 FPS)**.

### 5.3. Троттлинг интерпретатора Lisp
* Тяжёлая процедура `update-water-vc` (расчёт Френеля на 625 вершинах воды в Lisp), отнимавшая по 100 мс, переведена на вызов раз в 32 кадра (`mod 32`).
* Обновление матриц инстансов крон/пальм разнесено на `mod 4`, облаков — на `mod 12`.

## 6. Решённые дефекты и краевые случаи (Gotchas & Post-Mortem)

1. **Чёрный экран во вьюпорте редактора (BUG-FIX):**
   * *Причина:* Примитив `(gpu-present)` в режиме `OutputMode::Silent` сбрасывал `self.pending = 0`. Метод `flush()` при проверке `if !readback || self.pending == 0` пропускал операцию readback.
   * *Решение:* Введён сквозной флаг `Hal::readback_requested`, а в `flush()` убрана блокировка по `pending == 0` при запрошенном чтении.
2. **Перекрытие холма водой (Изоляция состояния `r3.blend`):**
   * *Причина:* Облака в конце кадра выставляли полупрозрачный режим `blend: 0.88`. При начале следующего кадра `clear_3d` очищал буфер, но не сбрасывал `blend`, из-за чего остров рисовался без записи в Z-буфер.
   * *Решение:* В `clear_3d()` добавлен обязательный сброс `self.r3.blend = 1.0`.
3. **Отсечение воды за кронами деревьев:**
   * *Причина:* Кроны рисовались с `depth_write: false`. Бесконечная плоскость воды не видела глубины крон и разрезала деревья горизонтальной линией горизонта.
   * *Решение:* Пайплайн `pipeline_inst_blend_tex_depth` включает запись глубины для плотной листвы (`blend >= 0.90`) вместе с отсечением пикселей в шейдере (`discard` по альфа-порогу).

## 7. Руководство для мейнтейнера

### 7.1. Правило ограничения потоков (Resource Guard)
> [!IMPORTANT]
> Любая сборка, проверка или запуск тестов обязаны использовать флаг `-j 1`:
> ```powershell
> cargo check -j 1                          # Проверка софтверного ядра
> cargo check --features wgpu -j 1           # Проверка аппаратного GPU-слоя
> cargo test --workspace --features wgpu -j 1 # Полный прогон 55 тестов
> cargo build --release --features wgpu -j 1 # Сборка оптимизированного релиза
> ```

### 7.2. Проверка работы сцены «Остров»
1. **Запуск веб-редактора:**
   ```powershell
   cargo run --release --features wgpu -j 1 -- --serve --wgpu --fps 60 --script assets/lisp/main_island.lisp
   ```
   Открыть `http://127.0.0.1:7300/`. Вьюпорт отображает живую 3D-сцену острова, песчаное дно, воду с пеной, пальмы и тени при ~30–35 FPS.
2. **Захват эталонных кадров:**
   ```powershell
   cargo run --release --features wgpu -j 1 -- --capture test_frames --every 5 --frames 15 --wgpu --script assets/lisp/main_island.lisp
   ```
   Кадры `test_frames/frame_*.png` должны содержать полноценное цветное изображение без артефактов и пропадания геометрии.
